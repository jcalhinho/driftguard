How it stays trustworthy

Issues by default. PRs only for safe mechanical fixes. No noise on every push.

🔔

Issues by default

A PR is only opened for strictly equivalent replacements (e.g. cache@v2 → @v4). Everything else is reported, never rewritten.

🔇

No noise

Each finding is reported once, keyed on the code content — not the line number. Editing a file doesn't re-open issues.

🔒

Read-only scan

The App downloads a tarball of the default branch into a temp dir and deletes it after. Nothing is executed.

📝

Contributable rules

Rules are plain YAML — no Python needed. Add a provider's breaking change in 10 minutes.

🆓

Free for everyone

Public and private repos, individuals and teams. Engine, rules, CLI and Action are MIT licensed.

Three ways to run

GitHub App (auto issues/PRs), GitHub Action (inline annotations), or CLI (local scan). Same rules everywhere.

Get started in 30 seconds

Pick whichever fits your workflow. All three use the same 53 rules.

Recommended

GitHub Action

# .github/workflows/driftguard.yml
name: DriftGuard
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4
      - uses: jcalhinho/driftguard@v1
        with:
          min-severity: warning

CLI

pip install git+https://github.com/jcalhinho/driftguard
driftguard scan .
driftguard scan . --min-severity critical
driftguard rules
